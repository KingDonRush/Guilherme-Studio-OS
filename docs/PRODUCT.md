# Guilherme Silva Portfolio

## Register

brand

## Users

The primary audience is international agencies, design studios, product teams,
and companies looking for a WordPress developer who can translate design into
maintainable implementation and build custom behavior when existing plugins are
too rigid.

Secondary audiences include remote-work recruiters, direct clients with
non-trivial WordPress projects, and technical peers evaluating public code.

Visitors need to understand:

- who Guilherme is;
- what kind of WordPress work he performs;
- what evidence supports that claim;
- how to discuss a project or hiring opportunity.

## Product Purpose

The portfolio exists to turn Guilherme's WordPress, Elementor, WooCommerce, and
plugin-development work into credible professional evidence.

It should generate qualified conversations for international remote work,
freelance projects, and recurring agency partnerships.

Success is not measured by visual novelty alone. The site must connect:

- polished implementation;
- real plugin behavior;
- navigable demonstrations;
- maintainable code;
- documented technical decisions;
- public GitHub authorship.

## Identity Architecture

### Guilherme Silva

Guilherme Silva is the commercial and professional identity. It is the name
used in the portfolio, proposals, client communication, hiring conversations,
LinkedIn, email, WhatsApp, and calls to action.

### kingdonrush

`kingdonrush` is Guilherme's developer identity: GitHub handle, code authorship,
repository history, technical documentation, packages, and developer-community
presence.

Whenever `kingdonrush` appears in a visual interface:

- it appears below `Guilherme Silva`;
- it has lower typographic and visual emphasis;
- it is accompanied by the GitHub logo;
- the icon and handle form one hyperlink to the GitHub profile;
- it never acts as a competing commercial brand or independent logo.

## Surface Architecture

### Portfolio Home

The home introduces Guilherme Silva, communicates his WordPress specialization,
shows selected evidence, and routes visitors to cases or contact.

### Plugin Cases

Plugin case pages belong to Guilherme's portfolio. Their job is to explain the
structural problem, the product decision, the defensible differentiator, and
the path to a working demonstration.

### Plugin Demo Sites

Demo sites are independent fictional businesses. They must behave and look like
credible client sites. They do not explain the plugin, the portfolio, or
Guilherme's technical decisions.

### Site Implementation Cases

Implementation cases prove design translation, content structure,
responsiveness, performance, and delivery quality. They must not be framed as
plugins or generic SaaS products.

## Brand Personality

Direct, precise, pragmatic, human, and technically mature.

The voice is confident without self-mythology, technical without unnecessary
jargon, and commercial without sounding like a generic agency.

## Anti-References

The portfolio must not resemble:

- a generic SaaS landing page;
- a dashboard or admin panel;
- an AI-generated card grid;
- a full-service agency template;
- a terminal-themed developer stereotype;
- a showcase of effects without evidence;
- a plugin catalog where every project shares the same visual identity.

Avoid invented metrics, clients, certifications, awards, job titles, years of
experience, and unsupported product claims.

## Design Principles

### Evidence Before Decoration

Visuals should prove identity, implementation quality, product behavior, or
project context. Decorative interface fragments are not evidence.

### One Surface, One Job

Home, case, institutional demo, listing, product detail, and cart state are
separate surfaces with separate information priorities.

### Design And Code Are Complementary

The portfolio should communicate that Guilherme works between design,
WordPress, Elementor, and custom code. It must not frame visual builders and
programming as opposing practices.

### Flexible Implementation

Show how projects adapt to real layouts, content types, and client workflows.
Do not let one demo brand define the visual meaning of a flexible plugin.

### Human First, Technical Proof Second

Guilherme Silva leads the client-facing story. `kingdonrush` supports it as
verifiable technical authorship.

## Accessibility & Inclusion

- Target WCAG 2.2 AA for public pages.
- Preserve readable contrast on photographic and dark surfaces.
- Keep body copy within comfortable line lengths.
- Provide visible keyboard focus and semantic navigation.
- Respect reduced-motion preferences.
- Never communicate state or project category through color alone.
- Keep touch targets practical on mobile.
